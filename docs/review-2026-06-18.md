### F1 [High] ~~커밋된 암호화 env 가 stale → 다음 배포가 pot-of-greed 시크릿을 지운다~~ (해소: ac2e199)

**해소 2026-06-18**: 라이브 `ops-vm.env`(21 키) 로 `ops-vm.enc.env` 재암호화 + round-trip 검증(decrypt 결과 라이브와 동일) 후 커밋. 아래는 원 진단 기록.


`compose/_hosts/ops-vm.enc.env` 는 BON-102 커밋(2026-06-13) 시점 그대로. 그 이후 추가된
pot-of-greed/ollama 시크릿 **11 개가 빠져 있다**: `POT_OF_GREED_DOMAIN`, `POG_TAG`,
`POG_PG_{USER,PASSWORD,DB}`, `POG_JWT_SECRET`, `POG_AUTH_USERS`, `POG_CHAINLIT_AUTH_SECRET`,
`OLLAMA_{BASE_URL,CLOUD_BASE_URL,API_KEY}`.

라이브 `ops-vm.env` 에는 20 키, 커밋된 enc.env 에는 10 키 (검증: 키 이름은 SOPS 가 암호화 안 함).

**즉각적 위험**: `scripts/deploy-ops-vm.sh:18` 이 매 배포마다
`sops -d ops-vm.enc.env > ops-vm.env` 로 라이브 env 를 무조건 덮어쓴다. 다음 routine 배포 →
`up -d`(line 24) 시 pot-of-greed-api 의 `PG_DSN`/`JWT_SECRET` 등이 빈값 → API 기동 실패.
재설치(L18) 시에도 복구 불가.

**조치**: 라이브 값으로 enc.env 재암호화 후 커밋.
```bash
ssh ops-vm 'cat ~/nexus-prime/compose/_hosts/ops-vm.env' > /tmp/ops-vm.env
sops --input-type dotenv --output-type dotenv -e /tmp/ops-vm.env > compose/_hosts/ops-vm.enc.env
shred -u /tmp/ops-vm.env
git add compose/_hosts/ops-vm.enc.env && git commit -m "fix: ops-vm.enc.env 재암호화 — pot-of-greed/ollama 시크릿 동기화"
```
(암호화는 `.sops.yaml` 의 age **공개키**만 필요 → 안전. 평문은 git 에 안 들어감.)
로컬에 sops+age 가 있어 즉시 실행 가능 — 진행 여부는 사용자 승인 후.
